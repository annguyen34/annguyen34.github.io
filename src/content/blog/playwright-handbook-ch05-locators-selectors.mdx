> **Chapter 5** trong series **Playwright + TypeScript: Nguyen's Handbook**.

Locator là thứ bạn dùng nhiều nhất trong mọi test. Viết locator tốt = test bền. Viết locator dở (hard CSS/XPath) = test break mỗi lần dev đổi class. Chapter này đi sâu vào *chiến lược chọn locator* và các kỹ thuật lọc/chọn nâng cao.

## 1. Thứ tự ưu tiên khi chọn locator

Hãy chọn theo thứ tự này:

**1. Theo role (tốt nhất):**

```ts
page.getByRole('button', { name: 'Submit' });
```

Tìm theo **role** accessibility + tên. Tốt vì nó phản ánh ngữ nghĩa, không phụ thuộc style.

**2. Theo label (tuyệt cho form):**

```ts
page.getByLabel('Email address');
```

**3. Theo text:**

```ts
page.getByText('Welcome');
```

**4. Theo test ID (ổn định):**

```ts
page.getByTestId('submit-btn');
```

Một điều quan trọng: `getByTestId` mặc định tìm attribute `data-testid`. Nếu codebase của bạn dùng tên khác (ví dụ `data-test`), bạn cấu hình trong `playwright.config.ts` qua `use: { testIdAttribute: 'data-test' }`.

## 2. Chaining — nối locator

Bạn có thể "khoanh vùng" rồi tìm bên trong:

```ts
await page
  .locator('.user-section')
  .getByRole('button', { name: 'Edit' })
  .click();
```

**Giải thích:** Dòng này đọc là "tìm khu vực có class `.user-section`, *rồi trong đó* tìm nút tên Edit, rồi click". Việc nối (chaining) giúp thu hẹp phạm vi tìm kiếm ⇒ cực hữu ích khi trên trang có nhiều nút "Edit", bạn chỉ muốn cái nằm trong khối user. Mỗi mắt xích trong chuỗi thu nhỏ tập kết quả của mắt xích trước.

## 3. Filtering — lọc theo điều kiện

```ts
await page
  .getByRole('listitem')
  .filter({ hasText: 'Product 1' })
  .click();
```

**Giải thích:** `getByRole('listitem')` khớp **tất cả** các mục danh sách trên trang. `.filter({ hasText: 'Product 1' })` giữ lại chỉ những mục **có chứa** chữ "Product 1". Đây là pattern kinh điển: lấy một tập element giống nhau (các dòng trong list/table), rồi lọc ra đúng dòng mình cần dựa trên nội dung.

Ngoài `hasText`, `filter` còn nhận `has` (chứa một locator con khác) - ví dụ lọc các dòng *có chứa* một nút cụ thể.

## 4. Làm việc với nhiều element

```ts
const count = await page.getByRole('listitem').count();
await page.getByRole('button').first().click();
await page.getByRole('button').nth(2).click();
```

**Giải thích:**

- `.count()` — đếm số element khớp. Lưu ý phải `await` vì nó là thao tác bất đồng bộ; kết quả trả về là một số.
- `.first()` — lấy element **đầu tiên** trong tập khớp.
- `.nth(2)` — lấy element thứ ba (index bắt đầu từ 0, nên `nth(2)` là element thứ 3). Tương tự có `.last()`.

> **Cảnh báo:** Dùng `.nth()` hay `.first()` khiến test phụ thuộc vào **thứ tự** element trên trang — nếu thứ tự đổi, test sai. Khi có thể, hãy ưu tiên `.filter({ hasText })` để chọn theo *nội dung* (ổn định hơn) thay vì theo *vị trí*.

> **Quy tắc chung:** Ưu tiên role-based locator — chúng phản ánh đúng cách người dùng tương tác với app và đồng thời thúc đẩy accessibility. Selector càng "user-facing" thì test càng bền trước các thay đổi về style/cấu trúc HTML.
